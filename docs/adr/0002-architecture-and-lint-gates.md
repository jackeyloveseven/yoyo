# ADR 0002:以质量门(architecture gates + ruff)强制架构与风格

- 状态:已接受
- 日期:2026-10-12
- 版本:2.0.1

## 1. 背景与决策

ADR 0001 的解耦约定若只靠自觉,会随时间漂移。2026-10 实测发现:`pyproject.toml`
早已配置 ruff 规则,但 CI 从不执行,导致 23 处 lint 违规(超长行、未排序导入)
无人拦截。

**决策**:架构与风格都必须由**自动门**在每次提交强制,而非靠 review 提醒:

- `check_v2_quality.py`:核心文件 ≤800 行、插件 ≤1200、生产文件 ≤2000;函数 ≤120
  行、≤8 参数、圈复杂度 ≤15;无重复 50-token 片段;无跨模型 import、无 GPU eager
  import、无 argparse 多边界、无 sys.path 篡改。
- `check_structure.py`:依赖方向、必需组件文件存在。
- `check_docs.py`:文档断链、重复片段/文档、总行数、机器 home 路径、`.claude/skills`
  或 `skills/` 根一律拒绝。
- `ruff check` + `ruff format --check`:代码风格与格式,纳入 CI。

## 2. 备选方案与后果

- **备选 A:靠 code review 把关。** 放弃:人会疲、会漏,规模上来后必然漂移(已实证)。
- **备选 B:只用架构门不管风格。** 放弃:风格漂移同样是维护负担,且免费可挡。
- **后果(正面)**:漂移在合并前被拦截,不积累;新人提交即知约束;`ruff format`
  一次性统一后只增量维护。
- **后果(约束)**:门是硬上限,合理的大文件必须先拆分或说服自己确实该改门——
  改门本身要写进 ADR,而不是放宽阈值了事。

> **预算修订记录(2026-10-13,ADR-0002 自身程序)**:`check_docs.py` 的
> `MAX_TOTAL_LINES` 自 v2 init 定为 2000,本次上调至 2200。触发:文档面从
> init 的 3 ADR/0 能力卡增长到 6 ADR/7 模型卡/10 契约卡 + 入门导读(39 文件,
> 远低于 MAX_DOCUMENTS=65,数量未失控);超支来自结构而非流水账。程序合规:先
> 做了一轮全量压缩(移除过时决策文本、与 ADR/契约卡重复的叙述、会腐烂的手工
> 符号清单,约 -50 行,见 BUILDING.md),确认剩余为活内容后才上调。`MAX_DOCUMENTS`
> 与 `MAX_FILE_LINES` 不变;下次再触顶,先压缩、后评估拆分文档,仍不得无声放宽。

## 3. 受影响的稳定契约

- `CONTRIBUTING_V2.md` 列出的全部质量门命令。
- CI(`.github/workflows/ci.yml`)必须包含这些门;新增门 = 改 CI + 本文档。

## 4. 同一迁移中移除的旧物

无文件移除;改动为 CI 新增两个 ruff 步骤与 23 处 lint 修复、`ruff format` 全量重排。

## 5. 验证与回滚边界

- **验证**:CI 每次提交跑全部门;本地 `check_*.py` + ruff + pytest 全绿方可合。
- **回滚**:单个门误伤可在该门脚本内精确豁免并注明理由,不得在 CI 里整体跳过。
- **何时可推翻**:当某门规则被证明系统性误报(而非个例),应开 ADR 调整规则,
  同时给出迁移期内存量代码的处理方式。

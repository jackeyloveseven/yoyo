# 跟着 YoYo 学后训练:给入门工程师的导读

这份导读假设你刚刚接触扩散/流匹配模型的后训练(post-training),不假设你看过论文。
目标:读完这一页,你能看懂仓库里任何一个零件在做什么,并知道下一步学什么。

**怎么用这一页**:按顺序读"五个概念";然后挑一个示例跑起来;再翻到"学习路径"。
遇到不认识的符号,查文末"符号表"。

---

## 一、五个核心概念(只讲这一遍)

后训练 = 把预训练好的生成模型,调成你想要的样子。所有方法都绕不开五个概念。

### 1. 加噪前向:x_t 是什么

扩散/流匹配模型的训练数据不是图片本身,是**同一个样本在不同噪声水平下的快照**:

```
x_t = (1 - t) · x_0 + t · noise        t ∈ [0, 1]
```

`t=0` 是干净图 `x_0`,`t=1` 是纯噪声。模型要学会:**给我任意 `(x_t, t)`,
告诉我干净样本的方向**。这个"方向"就是速度场:

```
v = noise - x_0                        所以反过来:x_0 = x_t - t · v
```

仓库里这条约定写死在 `nn/flow.py`,**所有算法零件都吃这个约定**——这是全仓库
最重要的约定,读懂它一半的零件都能读懂。

### 2. 损失 = 监督信号的数学名字

每个训练目标最终都是一句"什么和什么应该相等":

| 目标 | 一句话 | 数学形式 |
| :--- | :--- | :--- |
| SFT | 模型预测的速度应等于真实速度 | `‖v_θ - v_true‖²` |
| DPO | 好样本的概率应高于差样本 | 两个 logit 的差 |
| 蒸馏(DMD/OPD) | 学生采样分布应贴近教师 | 分布匹配 or 轨迹端点 MSE |
| RL(GRPO/NFT) | 高奖励样本的概率应上升 | 优势加权 + PPO 裁剪 |

看不懂某个目标的数学不要紧:**先看它说"什么和什么相等"**。仓库每个
`algorithms/<name>/` 目录都遵守这个结构——先读 docstring 第一段,它在用中文
讲清这件"相等"。

### 3. 教师、学生、EMA —— 三种角色

- **学生**:正在训练的网络,梯度回传到它。
- **教师**:提供监督的参考网络,梯度**不**回传它(永远 `detach`)。
- **EMA 目标网络**:学生权重的滑动平均(`target = 0.999·target + 0.001·student`),
  是"过去的自己"——比当时的学生更稳,用作基准。

**为什么这很重要**:后训练里"谁提供监督、监督是否被 detach"是一切讨论的起点。
YoYo 的零件强制这条边界:调用方忘了 detach,零件内部还会再 detach 一次
(防线,见 LCM 和 OPD 零件的实现)。

### 4. reward:把"好不好"变成数字

RL 系目标(GRPO/NFT)需要一个数来打分:身份保持用 ArcFace 余弦相似度、美学用
HPSv3++、指令遵循用 VLM 多维评分。**reward 是训练目标里唯一"由外部模型定义
好坏"的部分**,所以它的可信度决定 RL 的上限——reward-contract-audit 类的工作
就是防"分数在涨、效果在跌"。

### 5. 少步蒸馏:让模型走 2 步赶上别人 50 步

普通采样要几十步 Euler 积分。少步蒸馏训练一个模型,让它**一步或几步** 直接从
纯噪声跳到干净样本,画质接近多步。两条路线 YoYo 都有:

- **LCM**:学生一步映射的结果,要和"再退一步后的映射结果"一致(自举,无教师循环)。
- **On-Policy Distillation**:学生一步映射的结果,要和教师多步采样的终点对齐
  (跟随教师轨迹,每样本多几步教师前向,信号更稳)。

## 二、这仓库怎么帮你学

看一个零件,按这个顺序读:契约卡 `docs/algorithms/<name>.md` → 实现
`src/mmtrainer/algorithms/<name>/objectives.py`(docstring 是中文导读)→
示例 `examples/train_*.py` → 测试 `tests/v2/test_<name>.py`(失败模式在这里)。

**用 compose 选型**:不确定该用哪个目标?`mmtrain compose` 会问你模型、目标、
reward,然后告诉你该监控什么指标、画什么图、下一步做什么。不确定时问它,
比读十篇帖子快。

## 三、学习路径(从零到能改零件)

| 阶段 | 做什么 | 验收标准 |
| :--- | :--- | :--- |
| 1. 跑通 | `pytest tests/v2 -q` 全绿;跑 `examples/train_sft_edit.py` 看 loss 下降 | 97 测试通过 |
| 2. 读懂约定 | 读 `nn/flow.py` 的加噪/求解;用 `mmtrain compose` 生成两份蓝图 | 能讲清 `x_t`/`v`/EMA |
| 3. 读懂一个方法 | 读 LCM 契约卡 + 实现 + 示例 + 测试 | 能说清它和 DMD 的区别 |
| 4. 改一个数值 | 改示例里 `huber_c`/`num_distill_steps`,重跑,解释指标怎么变 | 实验卡上的指标解释对了 |
| 5. 导入新方法 | 按 `sourcing/intake-sop.md` 走 SOP,导入一个新损失 | 走完人机三个把关点 |
| 6. 改架构 | 读 `docs/adr/` 全部 6 篇,理解每个决策的边界 | 能提出 ADR-0007 |

**时间预期**:1→3 一两周有 CS 基础的业余时间;4→6 取决于你实际训不训模型。

## 四、常见困惑(来自真实问题)

**"为什么到处是 detach?"**
一切"基准"都必须被 detach:教师、EMA 目标、参考策略。忘了 detach,基准会被训练
信号拖着走,基准失效是后训练最常见的静默 bug。测试里专门有断言守它。

**"预训练和这些是什么关系?"**
预训练就是一张超大 SFT:干净图加噪、预测速度。本仓库不覆盖预训练,
但 SFT(`flow_sft_loss`)是它的最小形式。

**"什么模型能跑什么?"**
看 `docs/models/` 的能力矩阵,不要凭感觉——比如除了 Krea2,现有模型都不能同时
跑 RL 和 SFT 两系目标。

**"我的 loss 不降怎么办?"**
按晋阶梯来:CPU preflight → GPU no-update → one-update。多数"不降"其实是
形状/NaN/学习率问题,在 one-update 阶段就该抓住。

## 五、符号表(本仓库约定)

| 符号 | 含义 |
| :--- | :--- |
| `x_0` / `x_t` | 干净样本 / 噪声水平 `t` 下的样本 |
| `t` / `sigma` | 噪声水平,`[0,1]`,两种拼写指同一个东西 |
| `v` | 速度场(指向干净样本的方向) |
| `θ` | 学生网络参数 |
| `EMA` | 指数滑动平均 |
| `advantage` | RL 里样本相对组内平均的得分差 |
| `detach` | 从计算图切断,梯度不回传 |
| `cfg` | classifier-free guidance(推理期技巧,训练外) |

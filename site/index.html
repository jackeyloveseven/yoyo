YoYo 把扩散/流匹配模型的后训练拆成可组合的纯函数零件—— 加噪、ODE 求解器、损失函数、奖励后端、模型适配器各自独立、可单测。 SFT、DPO、蒸馏、RL 换的是零件，不是整套脚本。

问题

同一批数学，被抄了四遍

为 SFT 写一套脚本、为 DPO 抄一套、做 RL 再抄一套——模型加载、加噪、ODE 求解器、学习率、FSDP 的代码复制粘贴得到处都是，改一处要改十处，而且每套的符号约定都不一样，实验结果没法互相比。

脚本合集

  • 加噪公式每个 trainer 一份，符号不统一
  • 新算法 = 复制 129KB 的 trainer 主干
  • 换模型要重读一半训练逻辑
  • 测试只覆盖"能跑"，不覆盖静默 bug

YoYo 零件

  • 加噪 x_t=(1−t)x₀+t·noise、Euler/DPM2 写死在基座层，全仓库共享
  • 新算法 = 一个独立 loss 函数 + 注册一行
  • 新模型 = 25 行 BaseModelAdapter，立刻用全部目标
  • 97 个数值不变量测试守 detach 边界、零方差组、FP32 路径

选一个模型，看它能跑什么

这就是 mmtrain compose 的兼容性判定逻辑：每个目标声明它需要哪些模型能力，模型的已注册能力是这些能力的超集时才算可跑。数据由注册表离线内联，与 docs/models/README.md 的矩阵同源，由测试强制一致。

    诚实边界

    源码可用 ≠ GPU 就绪

    任何 baseline 从"能构造"到"能引用"，必须逐级拿 receipt，不可跳级。每级都有明确的失败模式要抓，跳过一级的结论不可信。

    1. 1

      CPU preflight

      组件可构造、契约成立

    2. 2

      GPU no-update

      前向数值有限、显存可控

    3. 3

      one-update

      一次完整更新，梯度非 nan

    4. 4

      checkpoint readback

      写出读回，SHA-256 一致

    5. 5

      冻结评估

      固定权重评估，登记 receipt

    当前所有目标都停在第一级之前的部分：launch_enabled=false、promotion_qualified=false。 状态从 WebTrainer 与 receipts 读，不从源码树状态文档读。

    上手

    五分钟跑通，纯 CPU 无需权重

    示例全部由单测守护，README 里的每个数字与代码同源，由文档同步测试强制一致。

    1. 安装 — pip install -e .（Python 3.10–3.13）
    2. 看零件 — mmtrain registry list 列出全部模型 / 目标 / 奖励插件
    3. 生成蓝图 — mmtrain compose 问答式给出指标、可视化与晋级建议
    4. 跑示例 — 从 SFT 到 RL 八个示例，各自返回真实指标
    $ git clone https://github.com/jackeyloveseven/yoyo
$ cd yoyo && pip install -e .
$ pytest tests/v2 -q          # 97 passed
$ mmtrain compose --model qwen_image_edit_2x \
    --objective image_dpo --reward none --output blueprint.md

    蓝图会列出该目标应监控的全部指标、该做的图与下一步晋级动作——可直接贴进实验记录。

    吸收体系

    论文到零件，有一条标准路径

    上游雷达监测 8 个活跃项目，import SOP 定义准入门槛与三个人工把关点。已完整走通两个案例。

    监测agent 拉上游变更、列候选
    →
    评估agent 读代码写摘要
    →
    吸收按架构门重写为零件
    →
    沉淀ADR + 契约卡 + 测试

    LCM 少步蒸馏 已吸收

    相邻 ODE 步的自举一致性，无需教师多步 rollout。数学对照 SimpleTuner 实现，未 vendor 任何框架代码。

    On-Policy Distillation 已吸收

    学生一步预测对齐教师多步 Euler 轨迹终点。约 30 行纯逻辑，与 LCM 互补，ADR-0005 记录三处有意差异。

    Miles 异步 rollout 暂不吸收

    三个支柱全深耦合在分布式系统里，抽不出独立纯函数零件。整体搬入等于推倒轻量 engine 重写——记录结论，不强吸。

    定位

    和 AI-Toolkit 的区别

    两者目标不同，不是替代关系：想快速给 FLUX 训个 LoRA、不想碰代码，AI-Toolkit 更顺手；想在多个模型上系统地做后训练、蒸馏、RL 研究，且要求代码可测、可复用、不重复，YoYo 更合适。

    维度AI-ToolkitYoYo
    组织方式配置驱动：往现成 trainer 框架里填参数零件驱动：注册表 + 适配器 + 纯函数，自己拼装
    核心文件训练进程是超大类（SDTrainer.py 约 129KB）零件是小函数，单文件强制 ≤800 行（质量门拦截）
    加新算法在 trainer 的扩展点内开发写一个独立 loss 函数丢进 algorithms/，注册一行
    加新模型用它的 model registry 接入写 25 行 BaseModelAdapter，立刻用全部算法
    RL / DPOmain 分支未见内置实现一等公民：10 个目标 + 7 个奖励后端
    质量保障社区驱动、迭代快，CI 不跑测试每次提交强制过 AST 门 + 97 数值不变量测试 + 文档门

    新模型

    Qwen-Image-Edit 2.x：1–3 张控制图多图编辑

    2509/2511 世代多图编辑模型，与原版 Qwen-Image 同 MMDiT 底座，差异在多控制流的拼接。

    维度qwen_image（原版）qwen_image_edit_2x（2.x）
    控制图1 张1–3 张（2509+ 图像拼接训练）
    diffusers 管线QwenImageEditPipelineQwenImageEditPlusPipeline
    文本编码器 / VAEQwen2.5-VL / Wan2.1-VAE相同（2.x 与原版共享）
    可跑目标5 个监督系目标同样 5 个：image_sft / image_dpo / image_opd / latent_consistency / on_policy_distill
    晋级状态源码可用源码可用；LoRA 靶点与 VAE 归一化常数需 GPU 首次晋级时核对

    防重影契约：img_shapes 里 noisy 流与每个 control 流各自记录 (1, H//2, W//2)——跨流共用同一 tuple 会让 MSRoPE 给两段相同空间位置， 跨注意力无法区分（invoke-ai#9155 的教训）。超出 1–3 张控制图直接 ValueError。

    入门

    给刚接触后训练的人

    导读从"x_t 是什么"讲起，不假设你看过论文。六个阶段，从跑通测试到能导入新方法。

    1

    跑通

    pytest tests/v2 全绿；跑 train_sft_edit.py 看 loss 下降。

    2

    读懂约定

    读 nn/flow.py 的加噪与求解；用 compose 生成两份蓝图。

    3

    读懂一个方法

    读 LCM 契约卡 + 实现 + 示例 + 测试，能说清它和 DMD 的区别。

    4

    改一个数值

    改 huber_c / num_distill_steps，重跑并解释指标变化。

    5

    导入新方法

    按 intake SOP 走完人机三个把关点，导入一个新损失。

    6

    改架构

    读全部 6 篇 ADR，理解每个决策的边界，能提出 ADR-0007。

    换零件，不换整套脚本

    接入一个新模型只要 25 行适配器，就能用全部现成的损失函数和求解器。
